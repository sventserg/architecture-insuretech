### Проблемы и риски

- **увеличение времени ответа**, вызовы производятся синхронно, кол-во провайдеров увеличится в 2 раза
- **увеличение вероятности ошибок**, при недоступности одного из сервисов, при превышении таймаутов
- **устаревшие данные о продуктах между обновлениями**
- **рассинхронизация данных между сервисами**, один сервис обновляет данные 1 раз в 15 минут, а другой 1 раз в сутки
- **сервис ins-com-settlement** раз в сутки запрашивает

### Решение
- добавлен брокер сообщений Kafka, в котором будут созданы топики для отслеживания изменения информации о продуктах и для отслеживания оформленных страховок
- для сервиса ins-product-aggregator добавлен инстанс базы данных, который будет хранить данные о доступных продуктах
- ins-product-aggregator с заданной периодичностью (раз в 15 минут) будет запрашивать данные о продуктах у подключенных провайдеров. При изменениях будет вносить их в БД, а так же в Postgres WAL
- core-app при оформлении страховки будет делать соответствующую запись в БД, а так же дополнительно в Postgres WAL
- debezium будет отслеживать изменения в соответствующих БД и публиковать сообщения в брокер Kafka
- core-app подписан на топик с изменениями данных о продуктах
- ins-comp-settlement подписан на топик с оформленными страховками
